# review — плагин каталога fntasy studio

Независимый ревьюер кода со свежими глазами. Проверяет одну правку по её заданию, запускает линтер,
проверку типов и тесты затронутых пакетов и выносит вердикт **«можно интегрировать»** или
**«вернуть автору»** с находками, привязанными к `файл:строка`. Подходит любому проекту — с
интерфейсом и без.

English: [README.md](README.md). Каталог: [fntasy studio](../../README.ru.md).

## Установка

```
/plugin marketplace add doossee/fntasy-studio
/plugin install review@fntasy-studio
```

Из терминала: `claude plugin marketplace add doossee/fntasy-studio && claude plugin install review@fntasy-studio`.

| Что добавляет | Как вызвать |
|---|---|
| агент `code-reviewer` | `@agent-review:code-reviewer`, или Claude передаёт ему работу, когда вы просите независимое ревью |
| `references/review-guide.md` | как писать одну находку; агент читает его сам |

Без системы плагинов: `cp plugins/review/agents/code-reviewer.md ваш-проект/.claude/agents/`.

## Как работает

- **Свежие глаза.** Агент получает задание и дифф, а не выводы автора. Если ему их всё же передали, он их игнорирует и пишет об этом.
- **Улики.** У каждой находки `файл:строка`; Critical по возможности воспроизводится (падающий тест или скрипт в черновой копии), вывод прикладывается.
- **Класс ошибки, а не один случай.** Нашёл один запрос без фильтра по клиенту — ищет все такие и перечисляет каждое место.
- **Проверки запускаются.** Линтер, типы и тесты затронутых пакетов — с командой и выводом. Что не удалось запустить, перечисляется.
- **«Что подтверждено» — обязательный раздел**: что проверено и оказалось верным, и как.
- **Не больше трёх кругов** ревью на одну правку. Дальше правка возвращается с советом разделить её или переделать.
- **Только чтение и запуск** (`Read`, `Glob`, `Grep`, `Bash`): в рабочем дереве автора ничего не правит, не форматирует, не коммитит и не ставит.

Зоны, общие для большинства проектов:

| Зона | Что проверяется |
|---|---|
| соответствие заданию | каждый критерий приёмки: где реализован и каким тестом доказан |
| права и доступ | каждая новая точка API, запрос, задача и действие проверяют, кому можно |
| изоляция данных разных клиентов | каждый запрос, ключ кэша, задача, выгрузка и путь к файлу ограничены клиентом |
| деньги | проведённые суммы не меняются на месте; идемпотентность; без float |
| миграции | проходят на данных реальной формы, обратимы, безопасны во время выкладки, без долгих блокировок |
| секреты | нет в коде, настройках, тестах, фикстурах и логах |
| тесты | падают без правки и проверяют поведение, а не моки |

Серьёзность: **Critical**, **Major**, **Minor**, **Nit**. Любой Critical, Major или упавшая проверка — «вернуть автору».

## Пример

```
@agent-review:code-reviewer Проверь ветку feature/partial-refund относительно main.
Задание: docs/tasks/REFUND-2.md (критерии приёмки в конце).
```

## Профиль проекта для ревью

Агент читает `.claude/review-profile.md` в проекте (или `REVIEW.md`, или `docs/review-profile.md`), а также
`CLAUDE.md`, `AGENTS.md` и `CONTRIBUTING.md`, если они есть. Профиль говорит, что в проекте особенного;
он дополняет зоны выше и не отключает их. Достаточно короткого:

```markdown
# Review profile
## Commands
lint: npm run lint · types: npm run typecheck · tests: npm test -- <path>
## Risky areas
billing/ (деньги), migrations/ (Postgres, выкладка без простоя), auth/
## Multi-tenant
да: в каждой таблице `tenant_id`; клиент берётся только из сессии
## Conventions
деньги в целых минимальных единицах; проводки только добавляются
## Decisions
сгенерированные клиенты в src/gen/ не ревьюим
```

Секретов и персональных данных в профиль не пишите.
