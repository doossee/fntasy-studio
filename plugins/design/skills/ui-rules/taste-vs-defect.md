# Taste or defect

A remark is a **defect** when you can show what the person loses on this screen: a step that fails, an error, time on a frequent task, a number that cannot be read, a group that is excluded, consent or money taken. Otherwise it is **taste**: one line at the end of the report, no score, and it never changes the verdict.

## The test

Before writing a finding, answer three questions:

1. **Who loses what?** Name the person (role from the profile) and the loss.
2. **Where is the evidence?** A step in the task walk-through, a measured number (contrast, size, time), a screenshot region, a standard. "Feels", "looks dated", "not modern" are not evidence.
3. **Would the opposite choice be just as valid?** If a reasonable designer could do the opposite with no loss to the user, it is taste.

## Remarks that sound convincing but are taste

| Remark | Why it is taste | When it becomes a defect |
| --- | --- | --- |
| "Use the golden ratio for the type scale" | No evidence that the ratio helps people; any clear scale works | Never by itself; only if sizes are too close to tell levels apart (TEXT-1) |
| "Colours don't follow 60-30-10" | A rule from interior design, no usability data | If the accent is used on many elements and the primary action no longer stands out (COLOR-3, LAYOUT-3) |
| "Blue feels calmer for a payments app" | Colour psychology is weak and cultural | If a colour breaks a meaning people rely on (red for success) or fails contrast |
| "This should follow the F-pattern" | F is what people do when a page gives no cues | If the key information is not where people look first (LAYOUT-5) |
| "Too much white space" / "too little white space" | Density is a style choice | If groups merge (LAYOUT-2) or the main content falls below the first screen (LAYOUT-5) |
| "Flat design looks cheap", "glassmorphism is dated" | Fashion | If a control no longer looks like a control (STATE-1, EXP-1) |
| "Rounded corners would be friendlier" | Brand choice | Never |
| "Use a serif for trust" | No usable evidence | Never by itself |
| "Add an animation, it feels static" | Motion is not required | Never; the opposite (motion that delays) is the defect |
| "Icons would look better without labels" | Cleaner look | Removing labels from non-universal icons is a defect (EXP-7) |
| "Only two font sizes — not enough hierarchy" | Two sizes can be enough | If headings and body cannot be told apart |
| "The competitor does it differently" | Not a user loss | If the convention is what users expect (EXP-1) and it is checked across several products, not one |

## The other direction: defects dismissed as taste

These are often waved away as "style" but are defects:

- Light grey text on white (measure it: COLOR-1).
- Text over a photo without a scrim (COLOR-1).
- Placeholder used as the only label (STATE-3).
- Icon-only navigation with unfamiliar icons (EXP-7).
- All-caps body text or long all-caps labels (TEXT-2).
- Removing the focus outline "because it is ugly" (STATE-1).
- An attractive screen where people still fail the task (HONEST-4).
