# Evaluation, 24.11.2026

Two independent reviewers (fresh agents, same model, no access to the keys) each reviewed the four held-out screens with `ui-rules` 0.5.0 and `tools/measure.mjs`. Each had only the skill, the screens and one line of context per screen. Findings were compared with the keys by hand: a finding matches when it names the same element and the same rule group.

## Results

| | Run 1 | Run 2 |
| --- | --- | --- |
| Planted defects found | 26 of 26 | 22 of 26 |
| Findings not in the keys | 4 | 5, plus one key defect split into two findings |
| — of them real defects the keys missed | 4 | 3 |
| — of them false (artefacts of the static mock) | 0 | 2 |
| Traps hit | 0 | 0 |
| Severity equal to the key (matched findings) | 19 of 26 | 18 of 22 |
| Severity within ±1 | 26 of 26 | 22 of 22 |

Per screen (found / planted): h1 courier route 6/6 and 6/6; h2 invoices (Arabic) 5/5 and 5/5; h3 pricing 8/8 and 5/8; h4 lessons 7/7 and 6/7. Run 2's misses: the decoy plan, the stacked emphasis (filed under ACT-3 instead of LAYOUT-3), the incomparable plan attributes, and the jargon title (filed under EXP-2 instead of TEXT-4). The last two are close calls under a strict matching rule.

Run-to-run agreement (same element and group reported by both, divided by all distinct findings): 25 of 34, about 74%.

The sample is small (four screens, 26 planted defects, one model) and the reviewers are the same model that wrote the skill: read the numbers as a signal about where rules are ambiguous, not as accuracy.

## What went wrong, and what changed

| Observation | Cause | Change |
| --- | --- | --- |
| Run 2 reported two 200% zoom failures caused by the mock's fixed page height; run 1 listed them as "not checked" | The method did not say what to do with framing artefacts of static mocks | `method.md`: zoom, reflow and scrolling on a static mock are "not checked" unless the defect is in the component itself |
| Run 2 missed the decoy plan and the incomparable plan attributes on h3, and filed the stacked ribbons under ACT-3 | ACT-3 and LAYOUT-3 overlap on pricing pages | ACT-3 and LAYOUT-3 state their border: emphasis is LAYOUT-3, comparability is ACT-3 |
| Both runs scored "Are you sure? Yes/No" with Yes focused, and overdue status shown only by tint, at 4; the key said 3 | The key was inconsistent with `severity.md` (data lost without noticing; hides what people must check) | Key h2 #1 and #2 raised to 4, with a note |
| Both runs found the dialog's focus escaping to the page behind, and run 1 the 320 px reflow on h3 | Real defects the keys did not plant | Added to the keys as "found in evaluation" |
| Both runs were unsure how to score manipulation in a learning product | `severity.md` measured loss only as time, money or data | `severity.md`: calibration rows for engagement mechanics |
| Both runs were unsure whether a one-direction swipe is a path-based gesture | PLAT-2 named WCAG 2.5.1 without saying | PLAT-2: the on-screen alternative is required whatever the answer; 2.5.1 is named for path-dependent gestures |
| A glyph used as an icon (⊘) was measured against the text threshold | COLOR-1 did not say | COLOR-1: a character used as an icon is judged as text (4.5:1) when in doubt |
| Unclear which side numbers align to in a right-to-left table | DATA-1 said "end-aligned" | DATA-1: align by the last digit, so the right edge of the numbers lines up, in both directions |
| Unclear whether Western or Eastern Arabic digits are correct | TEXT-5 did not say | TEXT-5: the profile decides; mixing them is the defect |
| Unclear whether three manipulation mechanics are one finding | `method.md` said "one cause, one finding" | `method.md`: one finding when one fix removes all; separate findings when the fixes differ |
| The measuring script reported "no visible focus" on an element focused on load | It compares focused and unfocused looks | Listed as a known false positive in `tools/README.md` |
| ACT-1 or ACT-4 for a frequent action placed out of thumb reach | Overlap | ACT-1 owns size, spacing and reach; ACT-4 owns priority |

## Status of the held-out set

These keys have now been used to change the skill, so the set is no longer held out. The next evaluation needs new screens.
