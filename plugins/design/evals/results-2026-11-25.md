# Evaluation of the reviewer on holdout-2, 25.11.2026

`design-reviewer` from the installed plugin (`ui-rules` 0.7.0, 53 rules) reviewed the four screens of `holdout-2/` twice, in separate runs, with one line of context per screen and no profile. A separate scorer compared the reviews with the keys and checked disputed claims in the page.

| | Run 1 | Run 2 |
| --- | --- | --- |
| Planted defects found | 30 of 30 | 30 of 30 |
| False findings | 0 | 1 (a fixed 820 px layout on an 820 px tablet called a defect) |
| Traps hit | 0 | 1 partial (asked for a one-step undo where "−" reverses the action) |
| Style-only items reported as defects | 0 | 0 |
| Severity equal to the key | 21 of 30 | 19 of 30 |
| Severity within ±1 | 29 of 30 | 27 of 30 |

Run-to-run agreement: 47 of 55 distinct findings (85%); the runs disagreed only on extra findings, never on planted ones. Cost: about $1 per screen per run.

**The keys missed real defects.** Both runs found defects the author had not planted, most of them only visible when the controls are used: a payment that goes through with no time chosen, scanner input lost when focus leaves the scan field, messages hidden under a fixed bar, a layout that breaks between 601 and 1000 px. They are added to the keys as "found in evaluation".

**Severity.** Where both runs disagreed with the key by two points, they followed `severity.md` (an AA failure that hides the number people must check is 4); the keys were inconsistent with the scale there and were raised. One key score was raised from 2 to 3 because the task cannot be finished on the screen.

**Limits.** Four screens, one model, screens written by a model. The author of the screens had not read the rules, but the reviewer and the scorer are the same model family. After this run the set has been used once; it stays useful for comparing later versions, but changes to the rules made because of it would make it no longer held out.
