# STUDIO-1 v1 — fantasy-studio: каталог из трёх независимых плагинов и два ревьюера

Задача для облачной сессии, репозиторий публичный: каждый пуш — публикация.

## Решение владельца (16.11.2026)

- Репозиторий переименовывается из `growth-studio` в **`fantasy-studio`**. Переименование на GitHub делает владелец; GitHub сохраняет переадресацию со старого адреса.
- Слова владельца: «Это два разных, не имеющих отношения друг к другу инструмента — нужно их разделить. И если мы не добавили наши ревьюеры туда, то нужно их добавить».
- Устройство: один репозиторий, плагины в папках `plugins/growth` и `plugins/design`.
- Независимый ревьюер кода — отдельный плагин `plugins/review`. Причина: он проверяет код, а не дизайн, и нужен проектам без интерфейса. Если владелец решит иначе, его перенесут в `design`.

## Что сделать

### 1. Каталог `fantasy-studio`

- **`.claude-plugin/marketplace.json`** — имя каталога `fantasy-studio`; три плагина, каждый со своим `source`:
  - **`growth`** — `./plugins/growth`;
  - **`design`** — `./plugins/design`;
  - **`review`** — `./plugins/review`.
- У каждого плагина:
  - `license: Apache-2.0`;
  - `homepage` и `repository` — `https://github.com/doossee/fantasy-studio`.
- Общего `plugin.json` нет.
- Проверка: `claude plugin validate .` и установка каждого плагина отдельно из локального каталога. Опиши, как проверял.

### 2. Разделение

- **`plugins/growth/`** — всё, что про рост:
  - навык `growth`;
  - инструменты `tools/*`;
  - `profiles/example`, `examples`;
  - документы `docs/{metrics,music,publishing,reels,voice}.md`;
  - `package.json`, `package-lock.json`, `npm run …`.

  Инструменты должны работать из новой папки: пути в скриптах, `npm run check`, `npm run examples`. Проверь запуском.
- **`plugins/design/`:**
  - навыки `ui-craft`, `ux-clarity`, `ui-audit`, `ux-audit`, `design-variants`;
  - агент `design-judge`;
  - новый агент `ux-reviewer` — ниже.

  Скрипты измерений `measure.mjs` должны работать из новой папки.
- **`plugins/review/`** — агент `code-reviewer` (ниже) и, если нужно, короткий справочник `references/review-guide.md`: как писать находки.
- **Общего кода между плагинами нет.** Нужное одному — копия в нём, как сейчас с `profile.mjs` и `browser.mjs` внутри инструментов.
- **У каждого плагина свой `README.md` и `README.ru.md`:** что делает, как поставить, примеры.
- **Корневой `README.md` и `README.ru.md`** — витрина каталога: три плагина, команды установки:
  ```
  /plugin marketplace add doossee/fantasy-studio
  /plugin install growth@fantasy-studio
  /plugin install design@fantasy-studio
  /plugin install review@fantasy-studio
  ```
- **Корневой `CLAUDE.md`** — переписать под новое устройство.

### 3. Агент `ux-reviewer` (plugins/design/agents/ux-reviewer.md)

Независимый ревьюер интерфейса. Работает по образцу ревьюера кода: выводы автора ему не передаются, он смотрит свежими глазами.

- **Основание суждения:**
  - задачи реальных пользователей проекта;
  - общепринятые публичные источники: эвристики Нильсена, Apple Human Interface Guidelines, Material 3, Fluent, GOV.UK Design System, WCAG 2.2.

  Навыки `ui-craft` и `ux-clarity` он читает как предмет проверки, а не как закон: помогает ли правило людям.
- **Пользователи и контекст проекта** — из профиля в репозитории проекта, например `.claude/review-profile.md`: кто пользуется, языки, устройства, рискованные действия. Формат профиля и пример — в README плагина. Без профиля ревьюер спрашивает или опирается на общие роли.
- **Как работает:**
  - смотрит работающее приложение (Playwright, снимки до и после) и снимки из отчётов;
  - проходит 2–3 задачи пользователя;
  - отделяет вкус от вреда.
- **Выход:**
  - вердикт: «принять», «доработать» или «вернуть»;
  - находки с серьёзностью 1–4 и уликой: снимок, шаг задачи, источник;
  - **«что выигрываем / что теряем»**;
  - отдельно — «где правило навыка навредило или промолчало».
- **Инструменты:** только чтение и запуск, без правки файлов.

### 4. Агент `code-reviewer` (plugins/review/agents/code-reviewer.md)

Независимый ревьюер кода со свежими глазами.

- **Суть:**
  - выводы автора ему не передаются;
  - находки с уликой `файл:строка`;
  - Critical по возможности воспроизвести;
  - назвать класс ошибки, а не один случай;
  - не больше трёх кругов ревью на одну правку;
  - отдельно — «что подтверждено»;
  - вердикт: «можно интегрировать» или «вернуть автору»;
  - запуск линтера, типов и тестов затронутых пакетов с приложенным выводом.
- **Зоны, общие для большинства проектов:**
  - соответствие заданию: каждый критерий приёмки — где реализован и каким тестом доказан;
  - права и доступ;
  - изоляция данных разных клиентов, если проект многопользовательский;
  - деньги: неизменность проведённых сумм, идемпотентность;
  - миграции;
  - секреты;
  - тесты, которые реально проверяют поведение.
- **Особенности проекта** — из профиля в репозитории проекта, например `.claude/review-profile.md` или `REVIEW.md`, если есть.
- **Инструменты:** только чтение и запуск, без правки файлов.
- **Ничего конкретного** о каком-либо продукте, компании или клиентах — общий метод.

### 5. Версии и чистота

- Плагины — версия `0.2.0`; в README — «что изменилось с 0.1».
- **Публичный репозиторий.** Не коммитить:
  - секреты;
  - данные реальных людей и компаний;
  - внутренние планы;
  - профили реальных продуктов.

  `profiles/example` остаётся вымышленным. Ни одного упоминания конкретного продукта или клиента в ревьюерах.
- **Перед сдачей:**
  - `npm run check` из `plugins/growth`;
  - проверка размера `examples`;
  - поиск секретов;
  - `claude plugin validate .`.

## Критерии приёмки

- Каталог `fantasy-studio` с тремя плагинами. Каждый ставится и работает отдельно.
- Инструменты роста и скрипты измерений дизайна работают из новых папок — проверено запуском.
- Агенты `ux-reviewer` и `code-reviewer` есть, только для чтения, без привязки к конкретному продукту, профиль проекта описан.
- README корня и каждого плагина на двух языках, команды установки верные, `CLAUDE.md` обновлён.
- Проверки зелёные, в отчёте — что именно запускалось.
